# Evidence guide: where first-issue signals live on GitHub

Use concrete evidence rather than labels alone.

| Family | Live GitHub evidence | Eval-bundle evidence |
|---|---|---|
| Repository health | archived banner; newest default-branch commits; latest release; maintainer replies | `archived`, last five commits, latest release, and maintainer response sample in Repo facts |
| Scope | issue body and discussion for a bounded change, acceptance criteria, settled design, or an umbrella/tracker | Issue and Comments sections |
| Existing work | assignees, open linked PRs, and current comments saying work is in progress | `assignees`, `linked PRs`, and Comments in Repo facts |
| Contribution policy | CONTRIBUTING, linked policy files, templates, and AI policy | `contribution policy` in Repo facts |

In eval mode, measure dates against the bundle capture date. In live mode, measure against today. An outright ban on AI-assisted contributions fails the policy check; disclosure, testing, and understanding requirements are conditions rather than bans. In Path Review, ignore classmates' claim comments under the classroom house rule in `scope.md`.
